### model_9000 (2026-11-05): 歩行中からの進入の追加学習

`model_7999` は**その場 (立位) から回り始める**分布しか持っておらず、歩行中に pivot へ
切り替えると落ちた (`scripts/rsl_rl/eval_pivot_overhead.py`、1.0 m/s 進入・ゲートを外した
expert 単体駆動で **転倒 29.7 %**)。`K1FlatTurnFinetuneCfg` の `reset_base` 速度
ランダム化 (±1.4 m/s) は「立位姿勢のまま滑っている」初期状態でしかなく、実際の進入
(遊脚・歩行中の関節速度・2 秒ぶんの歩行観測履歴) が分布に入っていなかったため。

`Isaac-Velocity-Flat-Transition-TurnFast` (`K1FlatTransitionTurnFastCfg`) で
`MultiExpertPPO` (learner=turn、歩行 expert = `best_walk/model_52700` を凍結) により
1000 iteration 追加学習した。歩行 expert が実際に歩いた状態から制御が渡るので、
状態注入 (gait-state bank) は不要。

| 1.0 m/s 進入・expert 単体 (256 env) | 転倒 | 回転時間 |
|---|---|---|
| model_7999 | 29.7 % | 0.74 s |
| model_9000 | **0.0 %** | 0.68 s |

立位スタートの性能は落ちていない (回転 0.80 → 0.72 s、停止→180°→歩行再開の合計
1.20 → 1.12 s、転倒 1.2 % → 0.0 %)。整定時間は 0.47 → 0.42 s。

## インタフェース

ONNX の入出力は**歩行ポリシーと完全に同一**。C++ デプロイ側のモデル読み込み・
バッファ確保のコードは変更不要。

```
入力  command      [1, 3]
      obs_history  [1, 100, 49]
出力  actions      [1, 12]
```

**ただしコマンド 3 枠に書き込む値の意味が歩行と異なる。**

```cpp
// 歩行ポリシー
command[0] = vx;  command[1] = vy;  command[2] = wz;

// 本ポリシー ← これに変える
command[0] = 0.0f;
command[1] = 0.0f;
command[2] = wrap_to_pi(psi_target - psi_current) / M_PI;   // ∈ [-1, 1]
```

`wrap_to_pi` は `atan2(sin(d), cos(d))`。`psi_current` は機体のワールド yaw 角。
**この変更を忘れてもモデルは正常にロードできてしまうので気づきにくい。**

`obs_history` の 49 次元の中身 (gait_phase 含む) は歩行と同一なので、そちらの
生成コードはそのまま使える。

### 引き渡し時の履歴初期化

歩行ポリシーから切り替える際は、**履歴を歩行時のものから持ち越さずタイル埋めする**
(最初の観測を 100 ステップ全部にコピー)。学習時の CircularBuffer も
`num_pushes == 0` で同じタイル埋めをするので分布が一致する。

歩行の履歴には `velocity_commands` 枠に非ゼロの vx/vy が入っており、本タスクの
学習データには **slot 0/1 が非ゼロの履歴が 1 サンプルも存在しない** ため、
持ち越すと完全な分布外になる。

### 最終到達角の精度 (`eval_turn_accuracy.py`, n=13025)

各コマンドの再サンプリング直前 (2 秒保持しきった時点) の残り角。

| 指令角 | n | 中央値 | p95 | <2° | <5° | 破綻 (>20°) |
|---|---|---|---|---|---|---|
| 0-50° | 3593 | 0.94° | 1.87° | 95.9% | 98.9% | 0.3% |
| 50-90° | 2860 | 0.95° | 1.80° | 96.3% | 98.6% | 0.9% |
| 90-130° | 2929 | 0.95° | 1.89° | 95.6% | 97.5% | 1.6% |
| 130-180° | 3643 | 0.93° | 2.11° | 94.6% | 97.0% | 2.2% |
| **全体** | **13025** | **0.94°** | **1.90°** | **95.5%** | **98.0%** | **1.3%** |

**中央値は全角度帯で 0.93-0.95° と一定**で、成功時の精度は指令角に依存しない。
平均が角度とともに増える (1.18 → 2.84°) のは破綻ケースの裾が伸びるためで、
精度そのものは劣化していない。

NOTE: 学習ログの `success_rate` は「5° 以内に**一度でも**入ったか」の二値なので
最終到達精度とは別物。精度は上表 (`eval_turn_accuracy.py`) を見ること。
評価時は `Isaac-Velocity-Flat-Turn-Finetune` を使う
(`Isaac-Velocity-Flat-Turn` だとカリキュラムが目標角を stage 0 = ±45° に戻すため
全角度帯を測れない)。

## 既知の性質

* **接地したまま足裏を捻るピボット旋回**をする (片足支持時間はほぼ 0)。
  人型の正当な旋回方法なので罰していない。摩擦 DR を広げても、足裏に
  torsional friction を入れても踏み替えは獲得しなかった。
* **yaw 方向の揺れは抑制済み** (`settle_ang_stillness` + `settle_ang_vel_l1`)。
  Isaac 上でゲート内 yaw 角速度は約 0.12 rad/s (1 Hz 振動なら振幅 ±1.1° 相当)。
* **揺れ抑制と到達精度はトレードオフの関係にある。** 抑制前の版 (2026-09-14,
  摩擦 DR U(0.25,1.4)・旧寸法・スピン抵抗なし) は中央値 0.43° / <2° 97.7% だったが、
  本版は 0.94° / 95.5%。yaw の揺れは「最後の数度を詰める機構」として実際に
  使われており、止めた分だけ精度が落ちる。自己位置推定・認識のために揺れを
  消す要件を優先した結果。
  (ただし本版は摩擦 DR・初期姿勢 DR とも厳しい条件で学習しているので、
   精度差には難易度差も含まれ、揺れ抑制単独の寄与はこれより小さい。)
