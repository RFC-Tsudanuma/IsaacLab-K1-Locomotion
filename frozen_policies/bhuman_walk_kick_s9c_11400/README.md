## B-Human から変えた点 (Stage 9 で足したもの。Stage 1〜7 の分は s7b_9400 の README と進捗ログ)

| 変更 | 値 | 理由 (測定) |
|---|---|---|
| 速度指令の目標点の横ずれの下限 `min_side_off` | 0.15 m (今まで 0.06 m + extra) | うまく蹴れた 132 場面では胴体がボールの線から 0.12〜0.18 m 横にいる。真後ろから来る場面では指令どおり 0.05〜0.08 m に寄り、蹴り足のつま先・すねで先にボールを押していた |
| ボールの近くで向く方向 `near_yaw_off_deg` | キック方向から蹴り足の側へ 20° (今まで 0°) | うまく蹴れた場面の胴体は当たる 0.6 秒前から 18〜20° 回っている (B-Human の姿勢「約 30°」と同じ向き)。0° の指令に逆らっていた |
| 回り込む側の切り替えのしきい値 `walk_side_hysteresis` | 0.05 m (B-Human 0) | 横ずれ 0.15 m だと側が変わるたびに目標点が 0.3 m 跳ぶ |
| 苦手な向きを多めに出す `weak_rel_prob` | 0.25 | 足の選び方が切り替わる rel -10〜+5° は一様な向きでは 1 割強しか出ない |
| 蹴り足の速さ合わせ `kick_foot_speed` | 重み 20 | 新しい指令で弱キックの差が 0.92〜1.01 m/s (蹴り足が距離によらず 3.0 m/s)。重み 4 では変わらず、20 で 0.67〜0.79 |

報酬の目標点 (B-Human `ball_walk_speed`) は変えていない。変えたのは方策に入る速度指令だけ。

## 実機で作る速度指令

学習と同じ式で作ること (`docs/bhuman_walk_kick_spec.md`「実機のキック側で作る速度指令」、MuJoCo の
`Sim.update_kick_state` / `walk_target` / `walk_command`)。値が違うと大きく崩れる (例: Stage 1 の値で指令を作ると
s7b 9400 の細かい格子の失敗 13 → 32、この方策に Stage 8 までの指令 (3 つとも 0) を入れると細かい格子で 10° 超 1820・失敗 646 / 1824)。

## インタフェース (ONNX `policy.onnx`)

```
入力  command      [1, 3]        (vx, vy, wz)  上の式の速度指令
      obs_history  [1, 100, 61]  歩行の 49 項 + キック用 12 項 (locomotion/history_layout.py KICK_EXTRA_TERM_SPECS)
出力  actions      [1, 13]       脚 12 (scale 0.5) + 歩行周波数のずらし (±0.5 Hz に clip して基本周波数に足す)
```
ボールは半径 0.095 m・0.29 kg。関節の目標は関節の可動範囲で切る。実機では歩行方策とキック方策を切り替えて使う。
`policy.onnx` は `scripts/mujoco/sim2sim_bhuman_walk_kick.py --export_only` の書き出しで、評価に使ったものとバイト単位で同じ。
