## 変更内容: 位相周波数のコマンド依存化

FlatEnv の歩行位相 (phase_obs / feet_phase) の周波数を、固定値 (1.6 Hz) から
速度コマンド依存に変更した。

- `||cmd_xy|| <= 1.0 m/s` → **1.5 Hz** 固定
- `> 1.0 m/s` → 線形増加し **1.8 m/s で 2.0 Hz** (それ以上も同じ傾き 0.625 Hz/(m/s) で外挿)
- 従来と同じ per-env ±0.05 Hz の startup ランダム化をオフセットとして加算

実装 (`mdp/events.py`):
- `compute_cmd_phase_freq()`: 速度→周波数の線形マッピング
- `get_gait_phase()`: 周波数が時間変化するため `2πft` の直接計算ではなく
  **毎ステップ `2πf(cmd)·dt` を積分**する位相アキュムレータ。コマンド再サンプル時の
  位相ジャンプを防ぐ。1ステップ内の複数読み出し (reward→obs) は
  `common_step_counter` で単一積分に制御。リセット直後 (`episode_length_buf==0`) は位相0。
- `randomize_phase_freq_offset()`: オフセットDR (flat_env_cfg で startup 登録)
- 観測と報酬は同一の位相バッファを共有 (`phase_obs` / `feet_phase`)

**実機デプロイ注意**: `onnx_inference.py` 等の実機側位相生成は固定周波数前提のため、
同じ「速度コマンド→周波数マッピング + 積分」を実装する必要がある。

## Extreme command カリキュラム (i系列, 2026-07-22)

課題: 上位プランナ (最適制御) はコマンド範囲上限付近を多用するが、一様サンプリング
では corner (vx・vy 同時上限 + 大旋回) がほぼ出ず、その領域・遷移で転倒する。

実装:
- `ExtremeVelocityCommand` (mdp/commands.py): 確率 extreme_prob で「|v|∈[0.7max, max]
  符号ランダム + 現在 yaw から 2.0〜π rad 離した heading (飽和 yaw)」を引く。
  extreme env は standing 抽選除外。prob=0 で Uniform と同一。
- `extreme_command_curriculum` (mdp/curriculums.py): num_steps (既定 10000 iteration; 関数内で common_step_counter÷48 換算) から ramp_steps かけて prob 0→0.35 に線形導入、完了後は
  resampling (0.5, 4.0) に短縮して極端コマンド間の速い遷移にも晒す。
- config_overrides の dict 対応で `curriculum.extreme_commands.params.num_steps` 等を
  override 可能。resume 時は common_step_counter が 0 に戻る点に注意 (num_steps=0 で即時化)。

結果 (i01: h07 を resume し extreme 即時有効で 15000it まで):
- extreme 分布下 (prob=0.35 + 速い resample) でも転倒率 1.2%、ep_len 995 と安定。
- 通常分布での回帰チェック (i02 probe、h07 の同条件窓と比較):
  lin 0.694→0.740, ang 0.647→0.676, phase 維持, err_xy 0.609→0.555,
  err_yaw 0.495→0.452, 転倒率 1.56%→0.63% (**半減以下**)。劣化なし、全指標改善。

### i03: 20000it まで延長 (2026-07-23)
i01 を resume し extreme 有効のまま 20000it へ。extreme 分布下の転倒率 1.2%→0.87%。
通常分布 probe (i04, 40-300 窓) では ang 0.676→0.695, err_yaw 0.452→0.427,
転倒率 0.63%→0.39% とさらに改善 (lin/phase は維持)。

最終ポリシー: `logs/rsl_rl/k1_flat_wtune/2026-07-23_01-16-19_i03_extreme_to20k/model_19996.pt`

## 上体(頭部)振動抑制 (j系列, 2026-07-23〜24)

課題: 歩行中に頭が振動する。FlatEnv モデルは上半身自由度なし (頭は Trunk 剛結合) の
ため、頭の振動 = Trunk の回転/並進ジッタ。h06 の振動 proxy (Episode_Reward ÷ weight)
では roll/pitch 角速度 0.51 (rad/s)² が支配的で、上下動 (0.024) の 20 倍。

新規報酬 `base_ang_acc_l2` (mdp/rewards.py): Trunk 角加速度 (角速度の有限差分) の
L2 二乗ペナルティ。角速度ペナルティが取りこぼす高周波ジッタ (速度小・加速度大) を
直接罰する。

結果 (5000it, seed 43, 基準 h06):
| run | ang_vel_xy/lin_z/com_jerk/ang_acc | hmean | 振動(ang_vel_xy) | fall |
|---|---|---|---|---|
| h06 | -0.25/-0.8/-1e-6/— | 0.6056 | 0.510 | 1.50% |
| j01 | -0.75/-1.2/-3e-6/— | 0.577 | 0.296 (-42%) | 1.40% |
| **j02 (採用)** | -0.75/-1.2/-3e-6/**-1e-5** | **0.591** | **0.311 (-39%)** | 1.76% |
| j03 | -0.5/-0.8/-1e-6/-1e-5 | 0.601 | 0.376 (-26%) | 2.49% |

知見:
- 同じ振動低減でも ang_acc 項がある j02 は j01 より追従を保つ (0.577→0.591)。
  減衰を「角加速度側」で受け持たせる方が速度追従と両立する。
- j02 の追従低下 -0.015 は seed ノイズ (±0.03-0.05) 内、転倒率も基準同等。
- 採用重みを flat_env_cfg.py に反映済み (ang_vel_xy -0.75, lin_vel_z -1.2,
  com_jerk -3e-6, base_ang_acc_l2 -1e-5)。
  → **k01 フルパイプラインで破綻し j03 相当に緩和** (下記 k系列)。

## 上下動 (lin_vel_z) 抑制の試み (p系列, 2026-07-31〜08-01) — 効果なしと結論

m04 への仕上げ resume (2500it, extreme 無効, flat_ori -40 維持) で lin_vel_z を増量:
| 構成 | lin | z_proxy (平均二乗 vz) | 判定 |
|---|---|---|---|
| m04 基準 (-0.8) | 0.735 | 0.02260 | |
| p01 (-1.6) | 0.748 | 0.02252 | 変化なし |
| p02 (-2.4) | 0.744 | 0.02206 | -2.4% (ノイズ内) |

p02 の学習中の z 推移も 0.0220→0.0212→0.0216 と完全にフラット。
**結論: 現在の歩容の上下動 (RMS vz ≈ 0.15 m/s) は lin_vel_z ペナルティに対して
飽和しており、3倍に増やしても減らない (追従への害もない)。倒立振子型歩行の
CoM 上下動は歩幅と脚運動学でほぼ決まる構造的な量のため、重み増では削れない。**
config は -0.8 のまま据え置き。ポリシーも m04 のまま (p01/p02 は採用せず)。

### q系列: base 高さ目標追従 (target 0.53) の仕上げ resume — これも不発

振動は歩容の骨格に埋まっている)。ポリシーは m04 のまま。
### r01: 新規フル学習 (lin_vel_z -1.6 + height track -50 を歩容形成から) — これも不発
20000it フルパイプライン (extreme 期崩壊なし・健全に完走)。標準 probe:

  ポリシー不採用、m04 のまま。

### 上下動抑制の総括 (2026-08-02)
3 方式 (lin_vel_z 増量 polish / height track polish / 両方入り新規フル学習) 全て失敗。
**z_proxy ~0.022-0.023 (RMS vz ≈ 0.15 m/s) はこの歩容ファミリの床**と結論。
倒立振子歩行の vaulting は歩幅で決まるため、残る構造的レバーは
**ケイデンス (位相周波数) の引き上げ** (歩幅短縮 → vaulting 振幅は歩幅に対し二乗で減少)。
ただし位相周波数はユーザー承認済み仕様 (1.5→2.0Hz) かつ実機 C++ 側と同期が必要。
